# dsh 0.1.1: the patch that lied, and models that cannot stop reasoning

Two findings from moving a working install from `deepseek/deepseek-v4-flash-0731`
on dsh 0.1.0-rc.7 to `z-ai/glm-5.3-flash` on dsh **0.1.1-rc.2**, measured
2026-08-27.

Both are the same shape as the failures this repo already documents: the
setting looks applied, nothing errors, and the thing you asked for is not
happening.

---

## 1. The patch silently stopped applying — and said "GOOD NEWS"

dsh 0.1.1-rc.2 added a **compat gate**, a per-protocol table listing every
compat field and whether a deployment may set it:

```js
const COMPLETIONS_COMPAT_GATE = {
	thinkingFormat: "offer",
	supportsReasoningEffort: "offer",
	...
	openRouterRouting: "withhold",     // <- knows the field, refuses it
	vercelGatewayRouting: "withhold",
};
```

`"withhold"` means upstream knows the field exists and has **decided you may
not configure it**. The rationale is in the error text:

> sets compat `"openRouterRouting"`, which is not configurable here: pi-ai's
> installed catalog sets it for the vendors that need it, so name that provider
> as the route instead

That rationale does not survive contact with the catalog. **pi-ai ships no
`openRouterRouting` for any model** — checked against
`@earendil-works/pi-ai/dist/models.generated.js`, zero occurrences. There is no
vendor for which the catalog "sets it". Withholding the field removes the only
way to express a provider pin, and OpenRouter honours pinning *only* as a
`provider` object in the request body.

### Why this was worse than a plain breakage

`patch-openrouter.sh` detected upstream fixes with a bare presence check:

```bash
if grep -q "openRouterRouting" "$TARGET" && ! grep -q "openRouterRouting: z.any()" "$TARGET"; then
  echo "GOOD NEWS: this dsh already declares openRouterRouting in its own schema"
  echo "The patch is NOT needed on this version. ... drop this script"
  exit 0
fi
```

On 0.1.1-rc.2 the string `openRouterRouting` **is** present — inside the code
that rejects it. So the script matched its own refusal, congratulated the user,
and advised them to stop patching. Following that advice removes the pin.

The local variant of this script had the same bug in its idempotency check
(`grep -q "openRouterRouting"` → `already patched`), which is how it was found:
a file that had never been patched reported itself as patched for four days.

**Presence of a field name is not evidence of support.** Check the
disposition — `"offer"` vs `"withhold"` — not the string.

### The failure it produced

The refusal is not scoped to the field. A profile setting a withheld compat key
is rejected **whole**, so the route never registers, and the error names
something else entirely:

```
dsh: NO_ADAPTER: no adapter registered for provider "openrouter"
```

Nothing in that message mentions compat, routing, or the patch. See
[05-troubleshooting.md](05-troubleshooting.md#no_adapter-no-adapter-registered-for-provider-x).

### The fix, and why it got smaller

`resolveModelCompat` was rewritten between rc.7 and rc.2 to be **gate-driven**:
it now iterates configured compat entries and admits whatever the gate marks
`"offer"`, instead of threading each field by hand. So the patch dropped from
three edits to two — the guard and the spread are no longer needed:

| dsh | edits | what |
|---|---|---|
| 0.1.0-rc.7 | 3 | schema, resolver guard, resolver spread |
| 0.1.1-rc.2 | 2 | schema, **gate `"withhold"` → `"offer"`** |

`patch-openrouter.sh` now detects the layout and applies the right set. The
schema anchor also moved: `compatProfile` grew from 3 fields to 20, so the
patch anchors on its last field rather than the whole object literal.

## 2. Reasoning you cannot turn off

This repo's headline claim is "reasoning actually off". **On some models that
is not achievable**, and the config that works elsewhere is rejected.

`z-ai/glm-5.3-flash` reports:

```json
"reasoning": {
  "mandatory": true,
  "default_enabled": true,
  "supported_efforts": ["max", "high", "low"],
  "default_effort": "max"
}
```

Three things follow, and each breaks a pattern this repo recommends:

**`effort: "none"` is rejected, not ignored.** OpenRouter's own guidance for
`mandatory: true` is *"hide disable controls and do not send `effort: "none"` —
the model rejects it."* Carrying over a working `reasoning: "off"` produces an
error, not a quiet fallback.

**There is no `medium`.** `supported_efforts` is `[max, high, low]`. `medium` is
one of the most common effort names and it is invalid here.

**The default is the most expensive setting.** `default_effort: "max"`, so
omitting the reasoning field entirely — the exact failure documented in
[04-reasoning.md](04-reasoning.md) — buys the *priciest* level rather than none.
The trap is unchanged; the cost of falling into it went up.

### What to configure instead

Declare only the levels the model accepts, and default to the floor:

```yaml
      reasoning: low          # the floor; "off" is REJECTED on this model

      models:
        - id: z-ai/glm-5.3-flash
          reasoningEfforts:
            low: low
            high: high
            max: max          # NOTE: no "medium", and no "off"
```

Omitting `"off"` is deliberate. Mapping it to something harmless would put a
rejected value one UI click away.

**Check before configuring.** `GET /api/v1/models` carries the answer per
model:

```bash
curl -s https://openrouter.ai/api/v1/models \
  | jq '.data[] | select(.id=="z-ai/glm-5.3-flash") | .reasoning'
```

`mandatory: true` → do not send `none`, and pick a default from
`supported_efforts` rather than assuming `off`/`minimal`/`medium` exist.

Measured after configuring `low`: **0 reasoning tokens billed**, versus the
5,502 that [04-reasoning.md](04-reasoning.md) records from an unconfigured route.

## 3. `supports_implicit_caching: false` does not mean "does not cache"

Every `z-ai/glm-5.3-flash` endpoint reports `supports_implicit_caching: false`.
Read literally, that retires prompt caching as a cost lever — the previous
route depended on ~95% implicit hit rates.

Measured instead of assumed. Two identical 7,144-token requests, back to back,
on Novita:

| | prompt | cached | hit | cost |
|---|---|---|---|---|
| cold | 7,144 | 0 | 0% | $0.000537 |
| warm | 7,144 | 7,104 | **99%** | **$0.000110** |

A **4.9x** saving. The flag evidently means "does not advertise implicit
caching", not "does not cache".

**Do not use that field to decide whether cache work is worth doing.** Measure
the second identical request. `scripts/watch-report.py` prints the hit rate per
exchange.

## 4. Picking the endpoint: first-party is not the default answer

`z-ai/glm-5.3-flash` is served by Z.AI, the model's own vendor. Z.AI is not the
best endpoint for it.

Three providers share the cheapest tier — identical pricing at $0.075 prompt /
$0.25 completion / $0.015 cache read, `discount: 0.5`:

| provider | p50 | p99 | uptime 5m | status |
|---|---|---|---|---|
| **Novita** | **1,722 ms** | 18,141 ms | 99.91% | 0 |
| GMICloud | 3,007 ms | 15,296 ms | 86.88% | **-2** (degraded) |
| Z.AI | 5,028 ms | **55,352 ms** | 99.19% | 0 |

Z.AI is 2.9x slower than Novita at p50 for the same money, and its 55-second
p99 is long enough to collide with `streamIdleTimeoutMs`. It also lists fewer
parameters — no `seed`, no `stop`, no frequency/presence penalty — which
matters for the capability reason in
[06-hard-pin-and-fallback-cost.md](06-hard-pin-and-fallback-cost.md).

DeepInfra still serves this model, at **2x** the price of the cheap tier
($0.15/$0.50). The provider that was correct for the previous model is not
automatically correct for this one.

**Re-run `scripts/probe-endpoints.py` per model.** Price, latency and
capability are per endpoint *and* per model; none of it carries over.

## Checklist for a model or dsh upgrade

- [ ] `probe-endpoints.py` for the **new** model — do not inherit the old pin
- [ ] Take `context_length` / `max_completion_tokens` from the **pinned**
      endpoint, not the model-level catalogue
- [ ] Read `.reasoning` from the catalogue: `mandatory`, `supported_efforts`,
      `default_effort`
- [ ] Re-run `patch-openrouter.sh` — npm replaces the file on every upgrade
- [ ] Confirm the gate actually says `"offer"`, not merely that the field name
      appears
- [ ] `verify-wire.py` — the config is not evidence; the wire is
- [ ] Send the same prompt twice and check the cache hit on the second
